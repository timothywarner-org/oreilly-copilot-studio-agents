# Co-instructor desk

**Start with the [run of show](run-of-show.md).** Keep this page, the current module guide, and the evidence record open while teaching.

## Division of attention

| Tim | Co-instructor or producer |
| --- | --- |
| Teach the decision, demonstrate, invite explanation | Track questions against the current objective |
| Read the visible result and explain what it proves | Check whether learners can see the source, input, and returned output |
| Give a short individual exercise | Post the exercise and remaining time in text |
| Decide whether to retry a failed step | Open the prepared recovery artifact and preserve the time boundary |

A single instructor can use the same checklist. It does not depend on a second live presenter.

## Opening talk track

**Say:** 'Today we're building an assistant for someone studying Azure fundamentals. You are the maker. We'll give the assistant a clear job, teach it where to find answers, add one small tool, and decide what we'd need before putting it in front of colleagues. You can follow along in Copilot Studio or make the same decisions in the workbook. Either way, I want you to predict what should happen before I press the button.'

**Do:** Show the four worksheet outputs and a short prepared end-state demonstration. Tell the class whether the demonstration is live or a recording. Save detailed architecture terms until the corresponding decision appears.

## Question triage

| Question | Response |
| --- | --- |
| 'Where is that control in my tenant?' | Check the authoring experience once. Give the documented reference and observer route if it differs. |
| 'Could this also use our help desk data?' | Reuse the current decision: approved source, access boundary, test evidence. Park connector setup. |
| 'Can it book my exam?' | Identify the absent tool and authority. The study tool returns advice only. |
| 'Which model is best?' | Begin with the approved available model. Compare the same cases against a candidate and judge quality, latency, and governance. |
| 'Can we build the other agent connection?' | Explain the boundary using the comparison. Keep implementation for follow-up. |

## Intervention prompts

- **Before a click:** 'What would you expect to change?'
- **After an answer:** 'Which passage supports that claim?'
- **After a tool call:** 'Where is the returned data?'
- **After a failure:** 'What can we still conclude?'
- **Before publication:** 'Who can use it, and what happens when it is wrong?'

## Recovery without losing the lesson

Retry once if the cause is clear and repairable in under two minutes. Otherwise load the rehearsed checkpoint or show a genuine recording. If neither exists, use the labelled paper example and mark the live demonstration incomplete. Preserve the learner exercise. Record what must be repeated after class instead of claiming the demonstration passed.

## Closing retrieval check

Ask learners, without reopening the earlier slides, to explain one instruction, one supporting source, one tool boundary, and one pilot condition. Invite a concrete first pilot and the governance question that must be answered. Point to independent labs and the export inspection task. Do not promise certification success or unrestricted publication from a trial.
